# Cisco Port Security – Secure MAC Addresses Lab

## 📌 Lab Overview

This lab focuses on **MAC address learning, MAC address tables, and switch port security** on Cisco Catalyst 2960 switches.

You will examine how switches dynamically learn MAC addresses, observe how traffic affects the MAC address table, and then configure **port security** to restrict which MAC addresses are permitted on PC-facing interfaces.

---

## 🎯 Objectives

By the end of this lab, you should be able to:

- Identify the MAC address of a neighboring switch.
- Examine a switch's MAC address table.
- Explain why end-device MAC addresses may not initially appear in the MAC table.
- Generate network traffic to trigger MAC address learning.
- Enable port security on access ports.
- Configure the maximum number of secure MAC addresses.
- Configure the port-security violation mode.
- Manually configure secure MAC addresses.
- Verify port-security configuration and secure MAC address entries.

---

## 🗺️ Suggested Topology

The topology consists of:

```text
PC1 ---- SW1 ---- SW2 ---- PC2
         F0/1    F0/1
PC1 → SW1 F0/2
PC2 → SW2 F0/2
```

### Device Roles

| Device | Role |
|---|---|
| PC1 | End device connected to SW1 F0/2 |
| PC2 | End device connected to SW2 F0/2 |
| SW1 | Access switch |
| SW2 | Access switch |

# 🧪 Lab Tasks

## Task 1 — Identify the Switch MAC Addresses

From the CLI of **SW1**, determine the MAC address of SW2.

Then, from the CLI of **SW2**, determine the MAC address of SW1.

Useful commands include:

```cisco
show mac address-table
```

You can also examine the switch's own hardware MAC address with:

```cisco
show version
```

or:

```cisco
show version | include Base ethernet MAC
```

Record the MAC addresses before continuing.

---

## Task 2 — Examine the Initial MAC Address Tables

Display the MAC address table on both switches:

```cisco
show mac address-table
```

Answer the following question:

> **Why don't the MAC addresses of PC1 and PC2 appear in the MAC address tables initially?**

### Explanation

Cisco switches learn MAC addresses by examining the **source MAC address of incoming Ethernet frames**.

If PC1 and PC2 have not generated traffic yet, the switches have not received frames containing their source MAC addresses. Therefore, their addresses will not necessarily appear in the MAC address table.

The switch learns a MAC address only after receiving traffic from that device.

## Task 3 — Generate Traffic Between PC1 and PC2

From PC1, ping PC2:

```text
C:\> ping <PC2-IP-address>
```

For example:

```text
C:\> ping 192.168.1.12
```

A successful result should look similar to:

```text
Reply from 192.168.1.12: bytes=32 time<1ms TTL=128
```

After the ping completes, check the MAC address tables again:

```cisco
show mac address-table
```

You should now see MAC addresses associated with the ports where the devices are connected.

### Expected Learning Behavior

The switches learn the source MAC addresses from the Ethernet frames generated by the PCs.

For example:

```text
SW1
-----------------------------------------
VLAN    MAC Address       Type       Port
1       <PC1-MAC>         DYNAMIC    Fa0/2
1       <SW2-MAC>         DYNAMIC    Fa0/1
```

And on SW2:

```text
SW2
-----------------------------------------
VLAN    MAC Address       Type       Port
1       <PC2-MAC>         DYNAMIC    Fa0/2
1       <SW1-MAC>         DYNAMIC    Fa0/1
```

Your actual MAC addresses will depend on the Packet Tracer topology.

# 🔐 Task 4 — Enable Port Security

Port security must be configured on the interfaces connected to the PCs.

In this topology:

- **SW1 F0/2 → PC1**
- **SW2 F0/2 → PC2**

First, make the interfaces access ports.

### SW1

```cisco
enable
configure terminal

interface fastethernet 0/2
switchport mode access
switchport port-security
```

### SW2

```cisco
enable
configure terminal

interface fastethernet 0/2
switchport mode access
switchport port-security
```

### Important Note

If you attempt to enable port security on an interface that is dynamically configured, Cisco IOS may reject the command:

```text
Command rejected: FastEthernet0/2 is a dynamic port.
```

The solution is to configure the interface as an access port first:

```cisco
switchport mode access
```

Then enable:

```cisco
switchport port-security
```

# 🔢 Task 5 — Configure the Maximum Number of Secure MAC Addresses

Answer:

> **How many MAC addresses are allowed on a port-security-enabled interface by default?**

The default maximum is:

**1 secure MAC address per interface.**

Although this is already the default, explicitly configure it on both switches.

### SW1

```cisco
interface fastethernet 0/2
switchport port-security maximum 1
```

### SW2

```cisco
interface fastethernet 0/2
switchport port-security maximum 1
```

Verify the configuration:

```cisco
show port-security
```

Expected output will include information similar to:

```text
Secure Port  MaxSecureAddr  CurrentAddr  SecurityViolation  Security Action
             (Count)        (Count)      (Count)
---------------------------------------------------------------------------
Fa0/2        1              0            0                  Shutdown
```

---

# ⚠️ Task 6 — Configure the Port-Security Violation Action

Answer:

> **What is the default action when a port-security violation occurs?**

The default violation mode is:

**Shutdown**

Configure it explicitly on both switches.

### SW1

```cisco
interface fastethernet 0/2
switchport port-security violation shutdown
```

### SW2

```cisco
interface fastethernet 0/2
switchport port-security violation shutdown
```

### Port-Security Violation Modes

Cisco supports three primary violation modes:

| Mode | Behavior |
|---|---|
| `protect` | Drops frames from unauthorized MAC addresses without increasing the violation counter |
| `restrict` | Drops unauthorized frames and increments the violation counter |
| `shutdown` | Places the interface into an error-disabled state |

For this lab, use:

```cisco
switchport port-security violation shutdown
```

# 🔑 Task 7 — Manually Configure Secure MAC Addresses

The final task is to manually configure the PCs' MAC addresses as secure MAC addresses.

You must first determine the MAC address of each PC.

You can use:

```text
ipconfig /all
```

or Packet Tracer's PC configuration information to identify the MAC address.

---

## SW1 — Secure PC1's MAC Address

PC1 is connected to:

```text
SW1 F0/2
```

Configure PC1's MAC address manually:

```cisco
interface fastethernet 0/2
switchport port-security mac-address <PC1-MAC-ADDRESS>
```

For example:

```cisco
switchport port-security mac-address 0002.16E2.2193
```

Replace the example MAC address with the actual MAC address of PC1.

---

## SW2 — Secure PC2's MAC Address

PC2 is connected to:

```text
SW2 F0/2
```

Configure PC2's MAC address:

```cisco
interface fastethernet 0/2
switchport port-security mac-address <PC2-MAC-ADDRESS>
```

For example:

```cisco
switchport port-security mac-address 0007.EC28.0631
```

Again, use the actual MAC address of PC2 in your topology.

# 💡 Key Concepts Learned

### 1. MAC Address Learning

Switches dynamically learn MAC addresses by examining the **source MAC address of incoming frames**.

### 2. MAC Address Tables

The MAC address table maps:

```text
MAC Address → Switch Port
```

This allows the switch to forward Ethernet frames intelligently instead of flooding every frame out every port.

### 3. Traffic Causes MAC Learning

If a PC has not transmitted traffic, its MAC address may not yet appear in the switch's MAC address table.

Generating traffic, such as a ping, allows the switch to learn the device's MAC address.

### 4. Port Security

Port security allows a switch administrator to restrict which MAC addresses are permitted on a switch interface.

### 5. Maximum Secure Addresses

The default maximum is:

```text
1 MAC address
```

For this lab, the value is explicitly configured using:

```cisco
switchport port-security maximum 1
```

### 6. Violation Action

The default violation action is:

```text
shutdown
```

It is explicitly configured with:

```cisco
switchport port-security violation shutdown
```

### 7. Manually Configured Secure MAC Addresses

A manually configured secure MAC address is associated with a specific interface:

```cisco
switchport port-security mac-address <MAC>
```

This prevents another device with a different MAC address from using that protected port without triggering a security violation.
