## 📖 About This Repository

This repository is my **hands-on CCNA and Network Engineering laboratory portfolio**, documenting practical configuration and troubleshooting of Cisco networking technologies.

Rather than focusing only on memorizing commands, these labs are designed to build the ability to:

- Configure Cisco routers and switches
- Design and implement small-to-medium network topologies
- Understand how network protocols operate
- Verify network behavior using Cisco IOS commands
- Identify configuration errors
- Troubleshoot connectivity problems systematically
- Implement routing and switching technologies
- Configure network security features
- Work with enterprise networking concepts
- Document technical configurations clearly

The repository currently contains **76 structured labs**, ranging from fundamental Cisco device configuration to advanced routing, WAN technologies, redundancy, monitoring, and troubleshooting scenarios.

This project forms part of my broader transition toward **Network Engineering, ISP/NOC operations, infrastructure support, and enterprise networking**.

# 🔍 Troubleshooting Methodology

A major goal of this repository is developing a **structured troubleshooting mindset**.

Instead of randomly changing configurations, I use a layered troubleshooting approach.

### 1. Physical Layer

Check:

```text
Cable
Interface status
Link lights
Device connectivity
```

Useful command:

```cisco
show interfaces status
```

---

### 2. Data Link Layer

Check:

```text
VLAN assignment
Trunk status
Native VLAN
STP
EtherChannel
Port security
```

Useful commands:

```cisco
show vlan brief
show interfaces trunk
show spanning-tree
show etherchannel summary
```

---

### 3. Network Layer

Check:

```text
IP addressing
Subnet masks
Default gateways
Routing tables
Next-hop reachability
```

Useful commands:

```cisco
show ip interface brief
show ip route
ping
traceroute
```

---

### 4. Routing Protocols

For dynamic routing:

```cisco
show ip protocols
show ip ospf neighbor
show ip eigrp neighbors
show ip bgp
```

---

### 5. Security & Filtering

Check:

```cisco
show access-lists
show port-security
show running-config
```

### 6. Services

Check:

```text
DHCP
```

# 🧪 Configuration vs Troubleshooting Labs

The repository includes both configuration and troubleshooting exercises.

### Configuration Labs

Focus on:

- Understanding a technology
- Building the topology
- Configuring devices
- Verifying operation
- Testing connectivity

### Troubleshooting Labs

Focus on:

- Identifying the fault
- Gathering evidence
- Analyzing configuration
- Isolating the affected layer
- Correcting the issue
- Verifying the fix

This distinction is important because real network engineering work involves much more than configuring a network from scratch.

# 🏗️ Example Network Engineering Workflow

A typical enterprise troubleshooting scenario can be approached like this:

```text
                     INTERNET
                         |
                    [Edge Router]
                         |
                  ----------------
                  |              |
             [Core SW1]------[Core SW2]
                  |
          -------------------
          |        |        |
       VLAN 10   VLAN 20   VLAN 30
       USERS     SERVERS   VOICE
          |
       Access
       Switches
          |
       End Hosts
```

The troubleshooting process would involve:

```text
Host
 ↓
Access Port
 ↓
VLAN
 ↓
Trunk
 ↓
STP
 ↓
SVI / Router
 ↓
Routing Table
 ↓
Routing Protocol
 ↓
WAN / Internet
```

This layered approach helps isolate failures efficiently.

# 💻 How to Use the Labs

## 1. Clone the Repository

```bash
git clone https://github.com/git25myhub/ccna-lab-series.git
```

```bash
cd ccna-lab-series
```

---

## 2. Install Cisco Packet Tracer

Install a compatible version of **Cisco Packet Tracer** through Cisco Networking Academy.

---

## 3. Choose a Lab

Start from Lab 001 and progress sequentially.

For example:

```text
001 → Router Security
002 → Router Security
003 → Router Security
004 → Serial Connections
005 → VLANs
...
054 → OSPF
...
067 → BGP
...
076 → Final Troubleshooting Review
```

---

## 4. Build or Open the Topology

Open the corresponding Packet Tracer topology and inspect:

- Devices
- Interfaces
- Connections
- IP addressing
- VLANs
- Routing requirements

---

## 5. Configure the Devices

Use the Cisco IOS CLI to implement the required configuration.

Example:

```cisco
enable
configure terminal

hostname R1

interface gigabitEthernet 0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown

end
write memory
```

---

## 6. Verify

Never consider a configuration complete simply because the commands were accepted.

Verify the actual network state:

```cisco
show ip interface brief
show running-config
show ip route
```

Then test connectivity:

```cisco
ping
traceroute
```

# 🧩 Troubleshooting Checklist

When a device cannot communicate, work through the following checklist.

### Physical

- [ ] Correct cable
- [ ] Interface connected
- [ ] Interface is up
- [ ] Correct interface selected

### Layer 2

- [ ] Correct VLAN
- [ ] Correct access port
- [ ] Correct trunk
- [ ] Native VLAN matches
- [ ] VLAN exists
- [ ] STP is forwarding
- [ ] EtherChannel is operational

### Layer 3

- [ ] Correct IP address
- [ ] Correct subnet mask
- [ ] Correct default gateway
- [ ] Correct routing table
- [ ] Next-hop reachable

### Routing

- [ ] Routing protocol enabled
- [ ] Correct networks advertised
- [ ] Neighbor relationship established
- [ ] Routes installed
- [ ] No incorrect filtering

### Security

- [ ] ACL applied correctly
- [ ] ACL direction correct
- [ ] Port security configured correctly
- [ ] Authentication credentials correct

### Services

- [ ] DHCP pool configured
- [ ] DNS configured
- [ ] NTP synchronized
- [ ] NAT translations occurring
- [ ] Syslog functioning
- [ ] IP SLA operational
